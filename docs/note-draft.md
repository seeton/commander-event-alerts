# 統率者の大型大会を見逃したくないので、コマフェスなどを月1回メール通知する仕組みを作った

コマンドフェストやコマンダーサミットに行きたい。

でも、大会情報は公式サイトやイベントページなど複数の場所に出るので、普段から追い続けるのは地味に大変です。気づいたときには申込開始から時間が経っていた、ということもあります。

そこで、日本国内の大規模な統率者イベントだけを探して、月初にメールでまとめて知らせる仕組みを作りました。

GitHubで無料公開しています。

https://github.com/seeton/commander-event-alerts

## 何が届くのか

現在は、次のようなイベント名を対象にしています。

- コマンドフェスト / CommandFest
- コマンダーサミット / コマサミ / コマサミサーガ
- プレイヤーズコンベンションのコマンドゾーン / Command Zone

反対に、毎週の店舗イベント、コマンダー交流会、コマンダー・パーティー、開催後のレポートなどは通知しません。

「統率者と付くものを全部送る」のではなく、遠征や事前申込を考えたくなる規模のイベントだけに絞っています。

## 一度知らせたイベントも、開催まで毎月知らせる

この仕組みは、新着情報を一度だけ送るものではありません。

例えば、10月10日に開催されるイベントが8月1日の時点で公開されていた場合、8月・9月・10月の月初に同じイベントを通知します。

一度見ただけだと「あとで予定を確認しよう」で忘れがちなので、開催前なら毎月届く仕様にしました。

新着通知というより、月初の予定確認リストに近いです。

## 仕組み

毎月1日の朝にGitHub Actionsが起動し、次の公開ページを確認します。

- 晴れる屋イベント検索
- マジック：ザ・ギャザリング日本公式
- プレイヤーズコンベンション公式

ページ内から対象イベント名を探し、開催日が過ぎたものを除外して、残ったイベントをResend APIでメール送信します。

Pythonの外部パッケージは使っていません。メール送信にもGmailのSMTPは使わず、通知専用のResendを利用しています。

## 無料で使える？

個人で月1回使う範囲なら、基本的に無料です。

GitHub FreeのPrivateリポジトリにはActionsの無料利用枠があります。この処理は月1回、通常は数分で終わるので、ほかで大量にActionsを使っていなければ十分収まります。

ResendのFreeプランは、記事執筆時点で月3,000通・1日100通までです。今回送るのは月に数通以下なので、こちらも十分です。

料金や上限は変わる可能性があるため、最新情報は公式ページを確認してください。

- GitHub Actionsの料金: https://docs.github.com/en/billing/concepts/product-billing/github-actions
- Resendの料金: https://resend.com/pricing

## 導入方法

### 1. テンプレートから自分用リポジトリを作る

次のページで「Use this template」を押します。

https://github.com/seeton/commander-event-alerts

作成するリポジトリはPrivateがおすすめです。

公開リポジトリでは60日間活動がないと定期実行が自動停止されることがあります。Privateなら通知専用リポジトリとして置いておきやすく、GitHub Freeの無料枠も使えます。

GitHub Actionsの有効化・無効化: https://docs.github.com/en/actions/how-tos/manage-workflow-runs/disable-and-enable-workflows

### 2. Resendに登録する

https://resend.com/

通知を受け取りたいメールアドレスで登録し、「API Keys」から送信専用のAPIキーを作ります。

独自ドメインを設定しない場合、Resendのテスト用送信元 `onboarding@resend.dev` から送れる相手は、そのResendアカウント本人だけです。そのため、Resendの登録アドレスと通知先は同じものにします。

### 3. GitHub Secretsを設定する

自分用リポジトリで、次を開きます。

Settings → Secrets and variables → Actions → New repository secret

登録するのは次の2つです。

- `RESEND_API_KEY`: `re_` で始まるResendのAPIキー
- `MAIL_TO`: 通知を受け取るメールアドレス

メールアドレスやAPIキーをソースコードに直接書く必要はありません。GitHub Secretsに入れた値は、リポジトリの画面やファイルには表示されず、通常の実行ログでもマスクされます。ただしワークフローは実行時に値を利用できるため、内容を確認していないワークフロー変更を取り込まないようにしてください。

### 4. テストメールを送る

リポジトリの「Actions」から「Commander Event Alert」を開き、「Run workflow」を押します。

「Send only a test email」をオンにして実行し、テストメールが届けば設定完了です。

最後に、チェックをオフにしてもう一度実行すれば、その時点で見つかった開催予定イベントが届きます。以後は毎月1日の09:15ごろに自動実行されます。

## メールアドレスは公開されない？

通知先とAPIキーは、GitHubのRepository secretsに保存します。

リポジトリ内のファイルには書かないため、コードを公開してもメールアドレスは見えません。僕が公開している元リポジトリにも、個人のメールアドレスや実際のAPIキーは入っていません。

ただし、APIキーをIssueやソースコードへ貼るのはNGです。誤って公開した場合は、コミットから消すだけでなく、Resend側でそのキーを削除して作り直してください。

## 注意点

これはWizards of the Coast、晴れる屋、BIG MAGICなどとは無関係の非公式ツールです。

公開ページの表記やHTMLが変わると、イベントを取得できなくなる可能性があります。また、すべての大型イベントを完全に網羅することも保証できません。

メールは予定を見つけるきっかけとして使い、開催日、会場、申込方法などは必ずリンク先の公式情報で確認してください。

取得漏れや「この大会も対象にしたい」という提案があれば、GitHubのIssueで教えてもらえると助かります。

https://github.com/seeton/commander-event-alerts/issues

## まとめ

大会情報を毎日追うほどではない。でも、コマフェスのような大きな統率者イベントは見逃したくない。

その間を埋めるための、小さな自動化です。

コードはMITライセンスで公開しているので、自分用に通知条件を変えたり、別のイベント向けに改造したりしてもらって構いません。

https://github.com/seeton/commander-event-alerts
